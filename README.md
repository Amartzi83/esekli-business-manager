# עסקלי — תצוגת ניהול העסק

דף הבית הוא אבטיפוס רספונסיבי בעברית. כרגע הנתונים בדף הם להמחשה בלבד.

## יומן העבודה

היומן מחובר למעטפת הקיימת ונפתח דרך הניווט הראשי. הוא כולל תצוגות יום, שבוע וחודש, יצירה ועריכה של אירועים, משתתפים, קישור למשימה ותזכורת. `calendar.js` מקבל שירות יומן דרך `window.businessAppContext.calendarApi` כשהמערכת המארחת מספקת אותו; בהיעדר שירות כזה הוא משתמש בנתוני הדגמה זמניים בזיכרון בלבד. אין עדיין שמירה משותפת או שליחת התראות.

## קווי עבודה (ביקורי גינות)

המודול (`visits.js`, `visits.css`) בנוי לפי עיצוב של שלושה מסכים, בפריסה משמאל לימין כמו בעיצוב:

- **קווי עבודה** — ביקורים לפי יום / שבוע / חודש / רשימה, מעבר בין תאריכים, מונים (צוותים, גינות, שעות, ק״מ משוער), התקדמות, סינון לפי סטטוס, לקוח וצוות, ותצוגה מצומצמת.
- **מסלול יומי** — צוות ורכב, מפה מאוירת (SVG) עם סיכות ממוספרות וקו מסלול, מיטוב מסלול לביקורים הממתינים, ניווט ב־Google Maps, דיווח תקלה, הערה וסיום יום.
- **פרטי ביקור** — תמונה, שיחה / וואטסאפ / ניווט, לשוניות פרטי ביקור, תקלות, משימות והיסטוריה, צילום תמונות (נשמרות ב־IndexedDB במכשיר), התחלה וסיום של ביקור.

הק״מ והמפה מחושבים לפי מרכז העיר שבכתובת, ולכן הם הערכה. תמונות הגינות ב־`images/` נלקחו מאתר M.Z Empire. הנתונים נשמרים ב־`localStorage` במכשיר הנוכחי בלבד.

## רשימת קניות, תזכורות ותיקי לקוחות

שלושה מסכים עם נתוני דוגמה, שנשמרים עם היסטוריה וגיבוי כמו שאר האפליקציה. הכרטיסים בדף הבית מציגים את אותם נתונים.

- **רשימת קניות** (`shopping.js`) — פריטים לפי קטגוריה, כמות, ספק, מחיר משוער וביקור משויך, סימון כנקנה (גם מדף הבית) וניקוי פריטים שנקנו.
- **תזכורות** (`reminders.js`) — לפי באיחור / היום / מחר / השבוע / בהמשך, אחראי, לקוח, ותזכורות חוזרות (יומית, שבועית, חודשית) שעוברות למועד הבא כשמסמנים אותן. כפתור הפעמון בשורה העליונה מציג את מספר התזכורות להיום.
- **תיקי לקוחות** (`customers.js`) — לקוחות פעילים, לידים ומושהים, פרטי קשר, חבילת שירות ומחיר, ביקורי הגינות של הלקוח (לפי שם הגינה) ויומן פעילות. בתיק הלקוח אפשר לבחור תמונה (העלאה, תמונה מביקור או תמונת גינה), והיא מוצגת בכל הביקורים של הלקוח בקווי העבודה.

העיצוב המשותף נמצא ב־`lists.css`. הטלפונים והמיילים בנתוני הדוגמה אינם אמיתיים.

## משימות

מסך המשימות (`tasks.js`, `tasks.css`) נפתח מהניווט הראשי ומהכרטיס "המשימות שלי" בדף הבית. הוא כולל הוספה מהירה, יצירה ועריכה של משימה (מועד, עדיפות, אחראי, קישור לביקור גינה והערות), סימון ביצוע, מחיקה, סינון לפי פתוחות / להיום / באיחור / הושלמו ולפי אחראי, וחיפוש מהשורה העליונה. המשימות מקובצות לפי באיחור, היום, מחר, בהמשך וללא מועד. הכרטיס בדף הבית והמונים מציגים את אותן משימות. הנתונים נשמרים ב־`localStorage` במכשיר הנוכחי בלבד, עד שיחובר שרת משותף.

## שמירה, היסטוריה וגיבוי

כל המודולים (משימות, ביקורי גינות, צוות ורכב, יומן והגדרות) שומרים דרך שכבה אחת, `store.js`:

- **שמירה** — הערך הנוכחי נשמר ב־`localStorage`, ובכל שינוי נשמרת גם תמונת מצב עם שעה ותיאור (מה נוסף, עודכן או נמחק) ב־IndexedDB (`esekli-history`). שינויים מהירים בתוך 20 שניות מאוחדים לרשומה אחת. נשמרים עד 400 שינויים לכל חלק.
- **גיבוי אוטומטי** — כל שעה כשיש שינוי, וגם לפני כל שחזור או ייבוא. נשמרים כל הגיבויים מ־48 השעות האחרונות, ואחר כך גיבוי אחד ליום למשך 60 יום.
- **תמונות שנמחקו** — עוברות לסל ונשמרות 30 יום.
- **קובץ גיבוי** — הורדה וטעינה של קובץ JSON עם כל הנתונים, ואפשר גם עם תמונות.

מסך **היסטוריה וגיבויים** (`history.js`, `history.css`) מאפשר לשלוף את המצב של כל חלק בכל תאריך ושעה, לראות היסטוריה של פריט בודד, ולשחזר פריט, חלק שלם או את כל האפליקציה. כל הנתונים נשמרים בדפדפן של המכשיר בלבד, ולכן חשוב להוריד קובץ גיבוי מדי פעם.

`server.js` מגיש את דף הבית ואת שני נכסי היומן המוגדרים במפורש. להפעלה מקומית השתמשו ב־`npm start` ופתחו `http://localhost:8080`.

בכל עדכון יש להעלות את מספר הגרסה (`?v=`) בקישורים לקובצי ה־JS וה־CSS ב־`index.html`, כדי שדפדפנים לא ישתמשו בעותק ישן מהמטמון.

נכסי היומן נטענים בנתיבים יחסיים כדי לעבוד גם באתר GitHub Pages של המאגר: `https://amartzi83.github.io/esekli-business-manager/`. האתר הוא אבטיפוס ציבורי; אירועי היומן נשמרים בזיכרון זמני בלבד ואינם משותפים בין מכשירים.

## אירוח פרטי

הדף מוגש דרך `server.js`, שמחזיר את `index.html` ואת נכסי היומן המוגדרים במפורש ולא חושף קבצים אחרים. לפרסום פרטי משתמשים ב־Google Cloud Run עם Identity-Aware Proxy (IAP), שמאמת כל בקשת דפדפן לפני שהשרת שולח את קובצי האתר.

הגדרות הפריסה:

- אזור: `me-west1` (תל אביב)
- שירות: `esekli-private-site`
- חובה להפעיל IAP ולהשאיר גישה אנונימית כבויה
- יש להעניק למשתמשים המורשים את תפקיד IAP-secured Web App User
- אין לפרוס את אותו דף ב־Firebase Hosting אם נדרשת הגבלת גישה לפני טעינת הקבצים

פריסת Cloud Run דורשת חשבון Cloud Billing פעיל. השרת מוגדר בחיוב לפי בקשות, אך שימוש בענן ובנייה עשויים לחרוג ממכסות חינם וליצור חיובים.
